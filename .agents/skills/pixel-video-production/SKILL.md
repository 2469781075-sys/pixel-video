# 像素视频制作

先读取 [画风与场景约束](references/art-direction.md)。需要配音、动画或成片时，再读取 [制作与交付流程](references/production.md)。按用户本轮要求选择静态检查图、局部小样或完整视频；延续已确认的风格和修改，不重复询问已经确定的事项。

## 执行流程

1. 查看当前仓库状态和已经保留的素材，识别用户本轮要修改的部分。将新版本写到独立目录或带版本的文件名，保留已确认的图与视频。
2. 保存原文并逐句拆分；记录每句对应的场景、视角、动作和配音。字幕与朗读保持原文措辞及标点，显示换行不改变文案。
3. 保持同一角色、教室平面布局、光源与像素网格。生成或编辑位图时使用可用的内置 `image_gen`，遵循工具实际接口；先查看本地参考图。调用 [imagegen](../imagegen/SKILL.md) 的素材一致性指导。
4. 优先复用现有 Python/Pillow/FFmpeg 渲染方式。将背景、人物、桌椅遮挡、窗框、窗扇、手和环境效果拆层，单独定义需要运动的部件。若选择 React/Remotion 工作流，再读取 [Remotion](../remotion-best-practices/SKILL.md)。
5. 每个镜头固定相机，用剪辑切换构图。以少量眨眼、手部动作、书页、雨点和风表现生命感；对齐像素坐标，避免整个背景漂移。开窗时切第一人称，开窗后改变窗外视野和室内光色。
6. 用户只要检查图时，交付静态图。用户要求正式完整视频时，完成配音、字幕、动作、混音、MP4 导出和检查，不把制作停在分镜阶段。
7. 检查实际编码视频的代表帧、完整解码、全部原文字幕和整条语音覆盖。另行检查人物关节、脚与地面接触、桌椅遮挡及窗户直线；程序检查不能替代这些画面检查。
8. 交付可访问的图片或视频、字幕和时间轴，保留来源及制作文件。按已经授权的范围保存到项目仓库，说明成片规格、验证结果和仍待人工确认的听感或画面问题。

## 配音与时长

使用用户选定的曼波声线及现有 GPT-SoVITS CPU 环境。已有完整音轨时直接复用；新文案按逐句 WAV 的实际采样数确定字幕和镜头时长。无需为读取 skill 更换声音服务或下载新的大模型。

当前《窗》成片的 21 句、139 秒朗读和 141 秒视频仅是这一篇文章的实测值。为新文章重新计算句数与时长，不套用旧数值。
