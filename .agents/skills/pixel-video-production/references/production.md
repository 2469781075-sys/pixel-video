# 制作与交付流程

## 原文、字幕和时间轴

将每篇新文章放到独立的作品目录，保存 `original.txt` 与 `sentences.json`。参考现有 `rpg-film/narration/sentences.json` 的格式：顶层 `sentences` 数组中每项有整数 `id` 和原文 `text`，其他场景字段可选。逐句拼接应重建原文，明确区分段落分隔与正文字符。

保留用户原文，包括“主播”“支走”“淫秽却无聊......”等措辞与标点。字幕整句显示，长句只作排版换行；不要改成摘要、短标题或语音识别后的改写。为每句记录音频、起止时间、场景、视角和动作。

生成音频后再最终确定镜头长度。计时来自实际 WAV 的采样数，包含明确记录的句间停顿，不能只按字数估算。最后一句需要完整播放，并保留适量收尾。

## 曼波配音

优先复用 `/workspace/tts-tools` 中已经配置的 GPT-SoVITS v2 曼波 CPU 环境。新任务中先检查依赖和模型是否存在；模型文件保留不代表语音服务还在运行。

```bash
/workspace/tts-tools/mambo-venv/bin/python /workspace/tts-tools/setup/preflight.py
```

需要合成且没有可用的现有服务时，在后台启动 `bash /workspace/tts-tools/setup/start_mambo.sh`，记录本次启动的进程和日志，不重复启动占用同一端口的实例。该脚本使用 CPU、离线基础模型及 `127.0.0.1:9880`。启动日志或端口连通只证明部分状态；必须生成一次非空、非静音的 WAV 才确认可用。

为新文章使用明确的路径参数，先用 `--limit 1` 输出到独立试听目录检查首句，再完整合成。示例中的路径应替换为实际作品目录：

```bash
/workspace/tts-tools/mambo-venv/bin/python /workspace/tts-tools/setup/narrate.py \
  --original /workspace/pixel-video/rpg-film/NEW-FILM/original.txt \
  --script /workspace/pixel-video/rpg-film/NEW-FILM/sentences.json \
  --output /workspace/pixel-video/rpg-film/NEW-FILM/narration
```

检查每句 WAV、整轨、`timings.json` 和 SRT；适当试听容易误读的句子。现有脚本默认原速、句间停顿 0.25 秒。它会输出逐句 WAV、全文 WAV 和时间轴；生成最终交付 MP3 时另用 FFmpeg。

如果只是复现现有《窗》成片，直接使用 `rpg-film/narration/mambo/mambo-narration.zip` 里的 WAV，无需启动语音模型。若环境中的工具确实丢失，先查看仓库 `rpg-film/narration/MAMBO-SETUP.md` 和 `mambo/mambo-ready-tools.zip` 中的已有安装工具及固定模型来源，再恢复；不要用新的配音服务替换曼波。

## 分镜、素材和动作

先按原文规划场景变化和语音覆盖。用户已经要求完整视频时，依据已有确认的视觉方向完成制作；用户要求先检查图片时，只生成指定图片。

生成素材时区分背景、人物及透明部件，保存最终选定版本及生成提示。按前后关系组织桌子、椅子、人物与窗台遮挡。先检查静帧的布局和关节，再为需要运动的部件增加局部关键姿态。长镜头应包含能表达句意的动作，避免只切换静态插画。

动画由时间或帧号确定，保证重现一致。相机在单镜头中固定，像素坐标取整；分场景切换、独立窗扇、手、眨眼、书页、风雨和水光可分别控制。对第一人称开窗检查关闭、开始移动、半开、全开和放下手的关键帧。

现有 `rpg-film/full-film/render.py` 是《窗》的专用渲染器，包含固定的素材、21 句时间轴与动作。它是复现和借鉴入口；制作新文章时复制或拆分到新作品目录，更新镜头、素材路径、时间轴和字幕，不能仅替换原文就声称已得到新成片。

## 当前成片的复现

从仓库根目录运行，使用当前项目的 Python 图像依赖、FFmpeg/libass 和 Noto CJK 字体：

```bash
python rpg-film/full-film/render.py --preview-only
python rpg-film/full-film/render.py
python rpg-film/full-film/verify.py
```

检查器会验证原文字幕、窗框及推拉动作、语音覆盖和完整视频解码。它依赖渲染时生成的 `_work` 音频；在新的检出中先完整渲染，再运行检查器。

## 新作品的成片检查

- 用 ffprobe 检查时长、尺寸、帧率、视频和音频流，完整解码声画以发现截断及损坏。
- 将 SRT 和烧录字幕去除排版换行后逐句与原文比对，检查每句的时间顺序、音频覆盖和显示区域。烧录字幕时避免播放器再默认显示同一条软字幕。
- 检查朗读开头、容易误读处、长句及结尾；背景音不盖过语音，峰值无削波。仅波形非静音不代表发音已确认正确。
- 从实际编码视频导出每个场景及动作关键时刻的帧，检查人物关节、站姿落地、坐姿支撑、桌椅遮挡、窗口直线、手臂连接、光色连贯及字幕可读性。
- 对同镜头不同帧检查固定背景没有位移、窗框不变形；不能只用一个小区域不变来宣称全部人物或整个镜头正确。

新文章重新计算预期句数、帧数、音轨长度和语音覆盖；不要沿用当前《窗》检查器中的 21 句、139 秒或 3384 帧断言。

## 交付

交付实际 MP4、可查看的代表帧、原文 SRT、音轨和镜头时间轴；保存渲染脚本、选定素材、来源及检查记录。用户此前无法打开本地文件链接，优先用对话内图片和已授权保存的 GitHub 文件或直接下载链接。

说明分辨率、时长、帧率、声音来源及检查范围。将仍需要试听或视觉确认的内容说清楚，不把自动检查当作用户已认可画面的证据。已确认版本继续保留，新作品和修订分别保存。
